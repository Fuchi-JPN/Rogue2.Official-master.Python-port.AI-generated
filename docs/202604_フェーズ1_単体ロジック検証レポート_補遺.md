### 2.2 詳細

#### P1-140: `add_traps()` の配置条件 — ⚠️ 要修正

**ファイル**: `actions.py:1389-1396` vs `trap.c:148-161`

**問題1: パーティ部屋での AND/OR 論理バグ**

C版 (`trap.c:154-155`):
```c
} while (((dungeon[row][col] & (OBJECT | STAIRS | TRAP | TUNNEL))
          || (dungeon[row][col] == NOTHING)) && (tries < 15));
```
- 継続条件: タイルが占有 **または** NOTHING（空）

Python版 (`actions.py:1394-1396`):
```python
if not (dungeon.dungeon[row][col] & (
        const.OBJECT | const.STAIRS | const.TRAP | const.TUNNEL)
        and dungeon.dungeon[row][col] != const.NOTHING):
    break
```
- `break` 条件: NOT(タイルが占有 **かつ** NOTHINGでない)
- = タイルが占有でない **または** NOTHINGである → break

C版は「占有 **または** NOTHING」のとき継続（breakはその否定）、Python版は「占有でない **または** NOTHING」のときbreak。**論理が逆**。実際には `and` を `or` に変更する必要がある。

**問題2: レベル別罠数の決定ロジックは一致** ✓

**修正案**:
```python
if not ((dungeon.dungeon[row][col] & (
         const.OBJECT | const.STAIRS | const.TRAP | const.TUNNEL))
        or dungeon.dungeon[row][col] == const.NOTHING):
    break
```

```c
rogue_can_see(int row, int col) {
```

```python
def rogue_can_see(self, dungeon, player, cur_room, row, col):
    rdif = row - player.row
    cdif = col - player.col
    if -1 <= rdif <= 1 and -1 <= cdif <= 1:
        return True
    rn = dungeon.get_room_number(row, col)
    if rn != const.NO_ROOM and rn == cur_room:

        if room and not (room.is_room & const.R_MAZE):

    return False
```
