## 5. 根因分析

### 5.1 モジュールレベル __getattr__ プロキシの限界

フェーズBで発見された最多のバグカテゴリは、**同一モジュール内での bare-name 変数参照**である。

Python の `__getattr__` はモジュール属性アクセス（`module.var`）でのみ呼ばれる。同一モジュール内で `ring_exp` と bare-name で参照すると、Python の LEGB スコープ解決によりローカル/グローバルを検索し、見つからなければ `NameError` となる。`__getattr__` は介在しない。

**修正方針**: モジュール内から GameState プロキシ変数を参照する際は、常に `GameState.xxx` と明示的に参照する。`__getattr__`/`__setattr__` プロキシは外部モジュールからのアクセス互換用に残す。

**残リスク**: `combat.py`, `use_actions.py`, `special_actions.py` の3モジュールについて AST 解析で bare-name 参照を全て検出・修正済み。他モジュール（`actions.py` 等）は `__getattr__` プロキシを持たないため問題なし。

### 5.2 メソッド引数の双方向呼び出し対応不備

`game.py` が `inv_manager.wear(obj)` のように引数付きで呼ぶ一方、`inventory.py` の `wear(self)` は引数なし。これは「対話選択モード」と「直接指定モード」の2つの呼び出しパターンが存在するが、Python版では後者が未実装だった。

**修正方針**: オプショナル引数 `obj=None` を追加。`obj` が渡されれば直接装備、`None` なら従来の対話選択。
